# 试用到期与归档

来源：S2–S4、S6。这里保留归档方法，不发布真实环境的到期日、调度标识或资源清单。

## 依赖一起收尾

云联络中心实例、Fabric 容量试用和 Notebook 排程分别有生命周期。历史案例中话单源先到期，刷新排程却仍继续，之后会报错；防覆盖只能保住旧数据，不能让数据继续更新。

在私有运维清单记录源服务到期、容量到期、计划停止和归档日期，并预留验证窗口。历史材料提到宽限与删除机制，但本次未联网核实，不能依赖固定天数保住成果，也不承诺自动续费或扣费行为。

## 到期前归档清单

1. 导出 Notebook 源码与参数说明，清除单元格输出和秘密值。
2. 备份模型、报表和必要配置定义，记录格式与对象依赖；定义备份不含模型数据。
3. 导出事实表、派生表、事件日志和状态区间的私有快照，记录时区、schema、刷新时点、行数与校验值。
4. 保存度量、关系、日期口径、Automation 文本与恢复步骤；配置引用只记录秘密引用名，不记录秘密。
5. 在隔离环境验证备份可解析、字段齐全、关键基线可重现。
6. 停止即将失效的排程，撤销不再使用的凭据和扩大的实例权限，记录最后成功刷新与数据截止时间。

不把报表定义备份、真实 CSV、原始 API 返回、PDF 或截图放入公开仓库。内部归档留在受控存储；公开分享只输出重新整理的文档、虚构示例和通用代码。

## 到期后仍可用的部分

Jira Automation 与 Fabric 解耦，容量不可用不会自动停止 Jira 规则；仍需单独检查其额度、身份和计划状态。看板应标记数据截止时间，避免旧数字被误认为实时数据。

转付费容量属于独立采购决策，先确认成本、数据恢复能力和暂停策略；本项目不执行采购、续费或任何远端操作。
