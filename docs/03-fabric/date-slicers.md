# DimDate 与日期切片器

> 实施状态更新（2026-11-14）：Route A 已在演示环境落地并浏览器验过——湖仓事实表加物理 `created_date` 列，DimDate 计算表 + 单向关系，20 个日期切片器（总览/CSAT/Raw Data/Trends/Daily 各 5 个），空日显示 0 的度量；数未变（CSAT 4.40/5/45.5%）。下文保留门槛检查步骤，供换环境时复用。

来源：S6 的方案、S8–S9 的后续状态。目标是统一创建日期筛选；早期 Direct Lake 计算列进关系受阻，改走湖仓物理日期列（Route A）后打通。

## 先过模型门槛

检查当前模型存储模式、日期对象支持及实际关系路径。优先在 Notebook/Lakehouse 中把 `created` 按约定时区转成物理 `created_date DATE`。物理日期列解决粒度问题，不自动保证计算日历与关系可用。

如果当前模型不支持目标计算表/关系，应评估物理日期维表或其他受支持的模型模式，并重新验数；材料没有证明这些替代路线已完成。门槛未过就停止报表部署。

只在支持 DAX 计算表的模型中使用下面的示例；范围按实际最早/最晚工单及规划期限调整：

```dax
DimDate =
ADDCOLUMNS (
    CALENDAR ( DATE ( 2026, 1, 1 ), DATE ( 2030, 12, 31 ) ),
    "Year", YEAR ( [Date] ),
    "Month", MONTH ( [Date] ),
    "WeekISO", WEEKNUM ( [Date], 21 ),
    "Day", DAY ( [Date] ),
    "ISOYear", YEAR ( [Date] - WEEKDAY ( [Date], 2 ) + 4 )
)
```

关系目标：`DimDate[Date]` 一对多到 `jsm_sla_facts[created_date]`，单向、活动。日期键唯一、非空、完整，并按模型要求配置日期表。不要直接把零点日期关联带时分秒的 `created`，也不要引入双向关系来掩盖筛选问题。

若模型支持 DAX 计算列，也可按年/月/日派生无时间日期，但必须先确认支持；日期时区语义不能改变。

## 五个切片器与页面

年、月、ISO 周数、日四个下拉，加 Between 日期范围，全部来自同一 DimDate。Between 只保留两端输入框的表现需参考自己版本的已验证 PBIR，不猜 JSON 属性。自然年与 ISOYear 在跨年周可能不同；周筛选应明确配合哪一种年。

总览与 CSAT 页优先配置；Lifecycle 两页及 Raw Data 页按各自日期语义设计。Lifecycle 的最新 report_date 是快照日期，不能被无意替换成创建日期；若同时支持创建日期筛选，要保留两者独立语义。

CSAT 默认按工单创建日期，而非回复日期。四个下拉与 Between 取交集；跨页同步另行配置与验收。已有书签可能恢复旧筛选，必须检查。

计数可用专用显示度量：

```dax
Ticket Count Display = COALESCE ( [Ticket Count], 0 )
```

此处 `[Ticket Count]` 代表自己的既有度量，不改变其去重与筛选逻辑。均值、评分和比例不能一律补零。连续日期趋势还需检查日期轴与显示无数据项。

## 验收

- 修改前保存相同刷新时点与筛选上下文的工单、SLA、分组、Lifecycle 和 CSAT 基线。
- 对比全选、单日、单周、跨年周、无数据日、多切片器交集、清除筛选。
- 检查空日期及范围外记录；明确日期对所有度量的传播，保留原有 `ALL` / `REMOVEFILTERS` 语义。
- CSAT 在无日期限制时与同快照基线比对，不能把不同日期的 82 单、87 单混为一组。
- Raw Data 导出核对真实键集合与事件集合，不能仅看页面卡片数字。
- 测试导航、钻取、工具提示、同步与书签，再宣布上线。
