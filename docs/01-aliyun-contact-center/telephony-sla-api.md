# 电话 SLA 报表与 API 自动刷新

来源：S3；入口背景见 S2。API 曾成功拉回四条记录并与 CSV 基线对账，本文不提供可访问的真实实例或凭据。

## 数据路线与表

```text
话单 API → 分页与字段映射 → ccc_call_records
                              ↓ 每日按语言/队列聚合
                         ccc_sla_daily → 语义模型 → 报表
```

主键使用 `<CALL_ID>`，去重后入库。统一记录开始、结束、排队、振铃、通话、保持、整理时长、队列、语种和状态。全空列使用显式 schema，避免推断失败。

## SLA 口径

| 指标 | 口径 |
|---|---|
| Offered | 进入统计范围的来电数 |
| Wait | 排队秒数 + 振铃秒数 |
| Abandon | 排队或振铃期间挂断，且等待超过 30 秒 |
| Short abandon | 同类挂断且等待不超过 30 秒；与 abandon 分开统计 |
| 放弃率 | Abandon / Offered；本案例分母仍含短放弃 |
| ASA | 已接电话的平均等待时间；无已接电话时为空 |
| AHT | 已接电话的处理时长均值；无已接电话时为空 |

S3 未给出 AHT 的完整组成公式，也未给出服务水平达标率的完整阈值/分母定义。若要新增这些度量，必须先约定通话、保持、整理是否计入，以及短放弃如何影响分母，不能把放弃率当作接通达标率。

## 刷新步骤

1. 使用私有身份 `<RAM_USER>`，通过受控秘密引用 `<SECRET_REF>` 获取凭据；区域和 `<INSTANCE_ID>` 属私有配置。
2. 调用 `ListCallDetailRecordsV2`，记录在 `Data.List`，分页信息位于 `Data` 中；按 `TotalCount` 和页号抓全。
3. 开始、结束时间按毫秒级 Unix 时间戳解析；内部统一保存时间基准，展示转换为 Asia/Shanghai，避免重复换时区。
4. 验证响应结构、分页完整性、主键唯一性及类型，再写明细与每日聚合。
5. 失败或异常空响应不覆盖历史表，保留刷新状态与最近成功时间。合法无数据窗口要与解析失败区分。
6. 手动验证成功后再排程；历史演示每十五分钟刷新一次。结束时间应早于依赖服务到期。

历史实践把凭据放入普通配置表，只是避免源码硬编码，并不等于安全秘密管理。本项目不复制这类配置表或临时笔记本。

## 权限排错

当时仅附加 RAM 只读策略仍报 `403` 与 `CDR:View` 缺失；尝试的自定义 Action 未注册而无效。将调用身份导入实例并授管理员后才调通，权限因此扩大，不能再宣称“纯只读采集”。

这只是当时环境的权限路径，不作为授予管理员的默认建议。实施时先核实实例角色与最小权限；如确需提升权限，明确范围、时限和演示后回收步骤。

## 验收基线：独立的四通快照

| 分段 | Offered | Abandon | Short abandon | Answered | 放弃率 |
|---|---:|---:|---:|---:|---:|
| Overall | 4 | 2 | 2 | 0 | 50.0% |
| 中文 | 3 | 2 | 1 | 0 | 66.7% |
| 英文 | 1 | 0 | 1 | 0 | 0.0% |

当次明细四行，每日聚合五行；ASA、AHT 为空。原始通话主键不公开。逐条比对主键集合、排队/振铃/等待、队列、语种和时间；个别地域、协议码与 IVR 秒数差异不影响该快照 SLA，但需记录差异。

接口成功却返回零行时，先检查是否误读顶层数组；不能用“HTTP 成功”代替入库与报表验证。权限修好后还暴露过全空列类型、时间戳字符串和聚合缺少时长字段问题。

结束演示时停排程、回收凭据和额外权限，保留最后成功时间与脱敏统计。历史实例到期早于排程结束，说明两个服务的生命周期必须一起管理。
