# Lifecycle Monitor：看见开着但没有推进的工单

来源：S4。JSM 管 SLA 时钟与提醒，Notebook 预计算跟进状态，Power BI 展示当前行动与趋势。

## 四类问题与时钟

| 类别 | 定义 |
|---|---|
| 无人认领 | 经办人为空，限定在需要跟进的状态集合 |
| 我方闲置 | 我方待处理状态中，至少一天没有更新 |
| 等客户待追 | Waiting for customer 且至少两天没有更新 |
| 待关闭 | Resolved 但未 Closed |

标记独立，一单可命中多类，不能相加当作唯一工单总量。等客户单列，不算处理人怠工。闲置分段：小于一天、一至两天、两至三天、三至七天、七至十四天、十四天及以上；建议左闭右开，明确边界。

闲置主时钟采用 Jira 原生 `updated`；仅看变更历史会漏评论等活动。状态停留时间从最近进入当前状态的事件算，不等于闲置时间。终态集合包含实际工作流中的 Closed、Canceled 等；Resolved 仍可进入待关闭集合。

## 数据层

| 表 | 粒度与职责 |
|---|---|
| jsm_sla_facts | 一行一单，现状、官方 SLA、updated_at、issuetype |
| jsm_assignment_log | 一次字段变更一行；保留经办人、状态、团队、开单组、解决组、优先级 |
| jsm_incident_daily | 每日快照；派生小时、工单年龄、状态停留、四类标记、分段 |
| jsm_status_intervals | 每次状态进入/退出区间和停留时长 |

历史采用 `/rest/api/3/search/jql` 与 `nextPageToken` / `isLast` 分页。展开的 changelog 不保证完整，截断时用逐单历史接口补齐。不要继续用已失效的搜索路径与 `startAt` 假定抓全。

派生口径集中在 Notebook；报表不再重复判断。每日快照按明确业务时区生成，同一天重复刷新应按快照键幂等写入。不要把已有本地朴素时间再做一次 UTC 转本地。

## 页面和队列

Daily Follow-up 展示六项 KPI、闲置分段、行动清单、组矩阵和处理人分布，页面取最新 report_date。Trends 展示逐日趋势、最老单、状态平均停留和事件下钻。下钻表必须把 `jsm_assignment_log` 接入模型，以工单键多对一关联事实表。

六个协调员队列分别覆盖未分配、SLA 已违约、等客户过期、高优先级、处理中闲置、Resolved 未关闭。JQL 先搜索验数再存队列；真实类型名可能带系统前缀，状态名不应凭经验猜。
