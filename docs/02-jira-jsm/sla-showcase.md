# JSM SLA Showcase：规格、复盘与验收

来源：S7 的目标规格、S4 的实施记录、S6 的较晚基线。S7 不是完成证明；没有证据的场景保留为待验证。

## 演示边界

只使用虚构工单，不连接生产邮箱或客户数据。站点统一为 `<JIRA_SITE_URL>`，工单用 `<ISSUE_KEY>` 表示。目标是让观众追溯“单票事件 → JSM 官方周期 → Fabric 分子分母”，而不是只看最终百分比。

| 配置 | 目标 |
|---|---|
| SLA | POC - 首次响应，120 工作分钟 |
| 开始 | 请求者创建工单 |
| 停止 | 客服首次公开回复；内部备注不算 |
| 暂停 | 等待请求者期间；退出后继续 |
| 工作日历 | Asia/Shanghai，周一至周五 09:00–18:00，排除周末与演示假日 |
| 对照日历 | POC - 24x7 |
| 重开 | 不默认创造第二个首次响应周期；实际多周期行为另行记录 |

记录实际界面的 Start/Pause/Stop 事件名称、目标匹配条件、日历与周期选择。如果版本没有目标条件，说明差异，不能悄悄换成解决时间。

## 验证脚本

1. 创建虚构单，确认真实 SLA 开始。
2. 添加内部备注，核对时钟继续；发公开回复，核对是否真正停止。
3. 验证等待请求者的暂停、恢复与剩余时间。
4. 验证超时场景；如现场用短目标加速，单独标识，不冒充 120 分钟规则。
5. 展示日历跨日与假日影响。周五 17:00 到周一 10:00，在无额外假日的上述工作日历中为 120 工作分钟；这可以是手算说明，不能冒充运行证据。

S4 仍记录过“公开回复未停止首次响应”的遗留，因此不能声称所有停止条件已经验通。

## 搬运到 Fabric

保留工单键、创建时间、状态、优先级、类别、解决责任组、官方 SLA 名称/目标/日历/周期状态/耗时/违约，以及事件时间和导出时区。CSV 缺周期或暂停信息时，从可用 API 补齐并标记来源；禁止用普通时间差代替工作分钟。

团队维度取解决责任字段或演示专用字段，不把当前经办人当作最终解决团队。SLA Rate 必须记录选定周期、达标分子、可比较周期分母与空值处理，统一采用 JSM 官方结果。

## 历史基线的正确用法

- 早期虚构 Excel 对照是自然分钟口径，明确算式为 95/141 = 67.4%；S7 另提 142 条样本，存在原始规格矛盾，未据此改算。
- JSM 的 120 工作分钟不天然等于 Excel 的 120 自然分钟，两个样本集不直接混算。
- S4 生命周期快照为 82 张单；S6 后续验收清单为 87 张单。后者是待核对的修改前基线，不是本次重验结果。

验收应交付配置口径、真实测试事件、官方 SLA 结果、字段映射和同筛选上下文的 Fabric 数字。工单创建成功、规则审计成功、报表刷新成功均不能单独替代验收。
